Title: SD and AI Agents: the Guide, the Knowledge Pack and the Skill
Subtitle: What an AI agent is given to work in SD Core Solo for Windows, how it is kept true, and the two rules that do not bend: the walls are walls, and what is not a wall is not a permission.

An AI agent (Claude Code, or any tool that reads files) that is asked to write SD BASIC meets a language that looks like OpenQM, UniVerse or D3 and is not. It guesses names that SD lacks, and the compiler's answer to a missing function is a complaint about a matrix nobody declared. This page describes what SD supplies to prevent that. **It supplies documents. It does not connect an agent to SD, it holds no key and it calls no model.** It is not an MCP door: Solo's MCP door is separate and off as delivered (see *The MCP Door* in the GettingStarted set). The installer copies two parts, as text, to the `agent-pack` folder under `sdsys` in the installation directory (`%USERPROFILE%\SDCoreSolo\sdsys\agent-pack`): the guide (`guide`) and the pack (`pack`). Nothing in SD reads them; they are there for you to copy to the machine where an agent runs, and an upgrade replaces them with the ones for the new version. The skill, the templates, the recipe and the generator are not installed; they are in the `sdb_ai\sd64\agent-pack` folder of the SD Core Solo for Windows source.

## What is in it

| | |
|---|---|
| **The guide** (`guide\sd-basic-guide.md`) | about eight thousand words: the language, the system around it, and what SD does not have, with twenty-odd worked programs, and a table of names that SD does not have. A sentence the guide could not check is marked `[unverified]` |
| **The knowledge pack** (`pack\`) | generated by `mkpack.py` from the sources of this product: one chunk for each TCL verb and query keyword, VOC record type, dictionary item type, format and conversion code, BASIC statement, function, `$mode` and `option`, message, `sd.conf` setting and key constant, with the file and line each came from. Real VOC records and real dictionary items are quoted verbatim. There is **no chunk for an account word**: Solo has none |
| **The skill** (`skill\sd-core-solo\`) | a Claude Code skill: `SKILL.md` and, under `references\`, the guide and the pack. An agent that is installed with it reads the guide first and looks items up by chunk id |
| **A CLAUDE.md template and the recipe** | for a project that lives in the Solo account, and for giving the agent a way in or a computer of its own. The recipe is described for the owner in the Getting Started documentation, on the page *Giving an AI Agent an Installation of Its Own* |

## Where the facts come from

The pack is not typed. Its lists are computed from SD itself: a verb is a VOC record of type `V`, a message is a file, a statement is a name in the compiler's tables, a setting is a branch of the configuration reader. Meaning that no program can state (what a query keyword does) is quoted from this documentation by heading. Each chunk names the file and line it came from.

## The rules that do not bend

**The walls are walls.** Solo has one account and two switches on it. What stops a session is the account password, `admin` (the administrator commands, and any change to the VOC), the `sh` and `os` switches (off as delivered: the shell, `os.execute`, a file outside the account, the embedded Python and the editors that run outside SD), the global catalog and the compiler's list of names that only SD's own programs may use. The guide shows the refusal each one gives, in a plain session that has not typed `admin`, and teaches no way round any. When one stops an agent, the instruction in the guide is to say which wall it was and to stop; whether to unlock `admin` is for the person who owns the computer, and the guide has an agent neither type, guess nor look for the password.

**What is not a wall is not a permission.** With the `sh` and `os` switches off, `sh`, `os.execute` and a path outside the account are refused (the page *Operating System Access* in the Getting Started documentation); with a switch on they run with the Windows user's own rights, and the switch is the user's to turn on (`set.os.access`), not the agent's. The guide shows each refusal, says what is open when a switch is on, and tells the agent to use an open one only for what the user asked and never to ask for a switch. It also warns of one misleading message: status 3035 on a write to the VOC is the `admin` wall, whatever the run-time text says about a full disk.

## What it does not do

It does not make an agent right; it makes the commonest mistakes cheap to avoid. It describes SD Core Solo for Windows at its stamp; items marked 2.0-0 may be missing from a released install. SD Core for Windows has its own pack, made from its own sources, and the two differ where the products do: `agent-pack\README.md` lists every difference and why.
